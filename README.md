# [Ремонт Пример — калькулятор ремонта](https://mansiks1.github.io/calculator-remont-demo/)

Одностраничное демо для портфолио на HTML5, CSS3 и JavaScript с ES-модулями.
Компания, тарифы, контакты и три отзыва вымышлены. Форма ничего не отправляет
и не сохраняет. Внешних библиотек, CDN, сборщика и зависимостей нет.

## Структура

- `index.html` — пустые семантические контейнеры и подключения.
- `content.js` — все тексты, цены, коэффициенты, сроки и настройки.
- `script.js` — отрисовка, чистая функция `calculatePrice` и форма заявки.
- `styles.css` — стили по блокам, значения оформления в `:root`.

## Как посмотреть локально

ES-модули нужно открывать по HTTP: двойной щелчок по `index.html` и адрес
`file://` могут блокировать импорт `content.js` в браузере.

Если установлен Python, откройте терминал в каталоге проекта:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:4173/index.html`. Остановка сервера — `Ctrl+C`.
В Windows вместо `python` можно использовать `py`.

Для проверки с телефона в той же доверенной Wi-Fi-сети запустите:

```powershell
python -m http.server 4173 --bind 0.0.0.0
```

Узнайте локальный IPv4 компьютера командой `ipconfig` и откройте на телефоне
`http://IP-КОМПЬЮТЕРА:4173/index.html`. При необходимости разрешите Python
доступ в частной сети в брандмауэре. Это временный локальный просмотр.

## Как поменять цены и коэффициенты

Редактируйте только `content.js`. Не меняйте `script.js` или разметку.

```js
// Базовая цена косметического ремонта за м²:
cosmetic: { title: 'Косметический', description: '...', price: 2800, tag: '...' }

// Коэффициент для двух комнат в массиве rooms:
{ id: '2', label: '2 комнаты', multiplier: 1.15 }

// Фиксированная надбавка в массиве options:
{ id: 'electrical', title: 'Электрика', description: '...', price: 65000 }

// Сроки в объекте deadlines:
deadlines: { cosmetic: 18, capital: 45, designer: 65 }
```

Это примеры отдельных записей; заменяйте соответствующие записи внутри
`site`, сохраняя структуру объекта и запятые. `id` должны быть уникальными.
Ключи `pricing` должны совпадать с ключами `deadlines`. Значения по умолчанию
в `settings` должны ссылаться на существующий тип ремонта и количество комнат.

Тексты редактируются в `brand`, `hero`, `calculator`, `result`, `form`,
`validation`, `about`, `reviewsHeading`, `reviews`, `contacts`, `footerNote`,
`navigation`, `meta` и `ui`. Диапазон площади, начальные значения и округление
задаются в `settings`. Дизайн меняется через переменные `:root` в `styles.css`.
Пороги медиазапросов указаны напрямую: CSS-переменные внутри условий
`@media` не поддерживаются.

Формула: `площадь × тариф × коэффициент комнат + сумма выбранных доплат`.
Итог округляется до ближайших 100 рублей. Форматирование — `Intl.NumberFormat`
для `ru-RU`, с неразрывными пробелами между разрядами. Повтор одного `id` опции
не удваивает доплату. Площадь может быть дробной; ползунок меняет её на 1 м².
Срок берётся только из `deadlines` по типу ремонта. Материалы не включены.

```js
calculatePrice(80, 'capital', '3', ['electrical']);
// { price: 492000, days: 40 }
```

## Как опубликовать на GitHub Pages

Публикация на GitHub Pages разрешена владельцем. Источник сайта — ветка `main`,
корень репозитория. Для первоначального включения использованы команды ниже;
повторять их после каждой правки не нужно:

```powershell
gh repo edit mansiks1/calculator-remont-demo --visibility public --accept-visibility-change-consequences
gh api -X POST repos/mansiks1/calculator-remont-demo/pages -f "source[branch]=main" -f "source[path]=/"
```

Адрес сайта: [mansiks1.github.io/calculator-remont-demo](https://mansiks1.github.io/calculator-remont-demo/).
Обновление сайта после `git push` может занять несколько минут. Статус можно проверить:

```powershell
gh api repos/mansiks1/calculator-remont-demo/pages
```

Все пути относительные, поэтому сайт работает в подкаталоге GitHub Pages.
Каждая последующая правка — отдельный осмысленный коммит и `git push`.
После включения Pages отправка коммита в `main` обновляет опубликованный сайт.

## Как подключить отправку заявки

В `script.js` найдите функцию `отправитьЗаявку` и комментарий о подключении
HTTPS-обработчика. Сейчас обработчик проверяет поля и показывает имитацию успеха.

1. Подготовьте собственный серверный endpoint или серверную функцию.
2. Считайте имя, контакт, согласие и параметры калькулятора до вызова `reset()`.
3. Отправьте их через `fetch` на endpoint; проверяйте `response.ok`.
4. На сервере повторите валидацию, ограничьте частоту запросов и передайте
   заявку в Telegram-бота либо в согласованный обработчик Google Forms.
   Для Google Forms простой альтернативой будет переход на саму форму.
5. Показывайте успех только после подтверждения сервером; при ошибке сохраняйте
   введённые поля и дайте повторить отправку. Все новые тексты добавляйте в `content.js`.

Токен Telegram-бота храните только на сервере. GitHub Pages обслуживает
статические файлы: серверную отправку разместите отдельно. При реальном сборе
контактов замените демо-тексты и укажите фактические условия их обработки.

## Проверка перед публикацией

- 50 м², косметический, 2 комнаты, без доплат → 137 500 ₽ и 14 дн.
- 80 м², капитальный, 3 комнаты, электрика → 492 000 ₽ и 40 дн.
- 300 м², дизайнерский, 4+ комнаты, все опции → 3 030 000 ₽ и 60 дн.
- 42,5 м², косметический, 1 комната → 106 300 ₽ и 14 дн.
- Пустая площадь, 9 или 301: ошибка и недоступная кнопка заявки.
- Заявка без согласия не отправляется; допустимы телефон или `@username`.
- Закрытие формы через Escape; возврат фокуса на кнопку и очистка данных.
- Узкий экран, клавиатурная навигация и объявление результата через `aria-live`.
